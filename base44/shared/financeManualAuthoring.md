# Mandatory Finance documentation contract

Finance navigation is generated by `financeFeatures` from `financeManualCatalog`, not by a second hardcoded tab list. The Finance manual is assembled directly from that same deployed catalog, so catalog changes appear on the next manual read without a generation wait or AI guesses. Verification metadata is refreshed after publication and weekly on Sunday at 03:00 Africa/Cairo.

For EVERY future Finance feature, section or report change:
1. Inspect its implemented calculations, source records, filters, permissions, exclusions and limitations. Never claim a source is connected or a filing is automated unless it is implemented.
2. Add/update the matching section in financeManualReports.js, financeManualControls.js or financeManualTaxes.js. A new section needs id, title, description, steps, accuracy checks, recommendations and reports. A report needs title, description, accuracy and recommendation. Validation rejects missing/duplicate entries.
3. Connect a new section's screen in the views map of FinanceWorkspaceTabs.jsx. Do not add a standalone tab that bypasses the catalog. Use the existing granular permission key on a restricted catalog section.
4. When adding a report within an existing section, add its guidance to that section's reports in the SAME change. When changing a formula or scope, update the corresponding interpretation and accuracy advice in the SAME change.
5. Run the catalog validation through refreshFinanceManual, and check that the new guide entry and actual report agree. Keep accounting amounts, source transactions, approvals and period locks untouched by documentation maintenance.

The scheduled job validates and records the current deployed definitions; it cannot discover arbitrary undocumented code added outside this contract. Never describe the manual as independently auditing accounting accuracy, discovering all business transactions, or automatically determining current tax law.
